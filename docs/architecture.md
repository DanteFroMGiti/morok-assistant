# Architecture direction

Зависимости направлены внутрь: UI и внешние интеграции используют модели ядра, но
ядро не импортирует PySide6, Linux API, Ollama или конкретные плагины.

```text
UI ───────────────┐
Animation ────────┼──> Core
Character packs ──┤
Plugins ──────────┤
System adapters ──┘

Application связывает модули при запуске.
```

## Правила развития

1. Системная функция, выполняющая действие, появляется как плагин. Источники состояния
   рабочего стола, такие как X11 idle, остаются узкими адаптерами в `system/`.
2. Плагин объявляет разрешения до запуска.
3. Общение модулей идёт через события или узкие интерфейсы.
4. Персонаж содержит только данные и ресурсы, но не исполняемый системный код.
5. AI предлагает типизированное действие; плагин проверяет его и только затем выполняет.
6. PySide6 остаётся на границе UI, поэтому машину анимации можно тестировать без экрана.

Такое разделение позволит позже заменить окно, формат атласа, AI-провайдера или
системный адаптер независимо друг от друга.
